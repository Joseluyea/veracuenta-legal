# Privacy Policy — VeraCuenta Uploader

*Last updated: August 18, 2026*

VeraCuenta Uploader ("the tool") is a personal, single-user desktop
application operated by the owner of the YouTube channel **VeraCuenta**
(https://www.youtube.com/@VeraCuenta). The tool generates original narrated
story videos in Spanish and uploads them to the owner's own YouTube channel.

## Who uses this tool

The tool has exactly one user: its developer, who is also the owner of the
YouTube channel it uploads to. It is not distributed, has no user accounts,
no website visitors, and no third-party users of any kind.

## Use of YouTube API Services

The tool uses **YouTube API Services** (YouTube Data API v3, specifically the
`videos.insert` and `thumbnails.set` endpoints) to upload videos and
thumbnails to the owner's channel.

By using the tool, its user agrees to be bound by the
[YouTube Terms of Service](https://www.youtube.com/t/terms). Google's
handling of data is described in the
[Google Privacy Policy](http://www.google.com/policies/privacy).

## Data the tool accesses and stores

- **OAuth credentials of the owner's own Google account.** The tool stores an
  OAuth token in a local file on the owner's computer. It is used solely to
  authenticate uploads to the owner's own channel, never transmitted to any
  party other than Google, and never leaves the owner's machine otherwise.
- **Nothing else.** The tool does not access, collect, process, store, share
  or sell any other personal information. It accesses no viewer data, no
  subscriber data, and no data belonging to any third party.

The tool runs entirely on the owner's local computer. It uses no cookies, no
analytics, no tracking, and no servers of its own. No data is shared with any
third party; the only external service it communicates with for YouTube
functionality is Google/YouTube itself, in the course of uploading.

## Revoking access

The Google account owner can revoke the tool's access at any time via the
[Google security settings](https://security.google.com/settings/security/permissions)
page, and additionally by deleting the locally stored token file.
